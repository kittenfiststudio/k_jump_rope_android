# 골반 기반 민감 점프 판정 v2

이 명세의 수치는 실측으로 조정할 초기값입니다. 실제 줄 회전이나 통과를 보장하지 않습니다.
판정은 Android/MediaPipe/Bitmap/Compose/DB에 의존하지 않는 순수 Kotlin `JumpDetector`에서 수행합니다.

## 신호와 보정

시작 후 3초 카운트다운 동안 점프를 세지 않습니다. 그 뒤 필수 8개 관절의 유효 좌표와
visibility ≥ 0.5를 확인합니다. presence는 제공될 때만 ≥ 0.5를 요구합니다.
서 있는 자세는 좌우 무릎의 2D 각도 ≥ 150°로 확인합니다. 각도 계산의 x축은 이미지 종횡비를 반영합니다.

어깨 평균 y부터 발목 평균 y까지의 거리를 몸 크기 S로 사용합니다. S가 0.15 미만이면 제외합니다.
골반·중심 x가 1초 동안 각각 S의 2.5% 이내에서 유지될 때 평균 기준선을 확정합니다.
발목은 유효한 전신 인식과 몸 크기 산정에 사용하지만 상승·착지·보정 안정성의 필수 동작 조건으로 사용하지 않습니다.
보정 도중 움직이면 안정 구간을 다시 시작합니다.

- 골반 상승 = (보정 골반 y − 현재 골반 y) / S
- 좌우 발목 상승 = (각 발목 기준 y − 현재 발목 y) / S
- 양발 신호 = 필터링한 좌우 발목 상승의 최솟값. 개발 화면의 참고 지표이며 카운트 승인·거부에 사용하지 않습니다.
- EMA α = 1 − exp(−Δt / 45ms)
- 골반 속도 = 필터링한 상승 변화 / Δt(초)

몸 크기는 매 프레임 즉시 재계산해 나누지 않습니다. 기준선·몸 크기·중심 x는 안정된 GROUND에서만
4초 시간상수로 완만하게 갱신합니다. 분석 좌표는 이미지 공간이며 실제 점프 높이가 아닙니다.

## 상태 전이

`CALIBRATING → GROUND → RISING → FALLING → LANDING → GROUND`

- GROUND → RISING: 골반 상승 ≥ 0.0036S, 상승 속도 ≥ 0.016S/초.
- RISING → FALLING: 골반 속도 ≤ −0.01S/초. 이때까지 골반 신호의 peak를 기록합니다.
- FALLING → LANDING: 골반 상승 ≤ 0.015S로 기준선에 복귀하고,
  peak 골반 상승 ≥ 0.007S가 확인되어야 합니다. 양발 상승량은 요구하지 않습니다.
- LANDING: 기준선 복귀가 45ms 유지되고 주기와 이전 이벤트 간격이 최소 180ms 이상일 때 한 번만 이벤트를 만듭니다.
- 최소 진폭 미달이면 횟수를 추가하지 않고 GROUND로 복귀합니다. 미완료 주기는 세지 않습니다.
- 공중 주기가 1800ms를 초과하면 폐기하고 다시 보정합니다.

필수 관절 누락, 250ms 초과 입력 gap, 이전 프레임 대비 중심 x/골반 y가 S의 35% 초과 이동,
기준 중심 x에서 35% 초과 이동, 몸 크기가 기준보다 25% 초과 변경되면 진행 중 주기를 폐기합니다.
추적을 회복하면 1초 동안 기준선을 재확인하며 누락 구간의 점프를 추정하지 않습니다.
중복·역순 시각은 판정 상태와 기준선을 변경하지 않습니다. 같은 입력·config·sessionId는 같은 이벤트를 만듭니다.

## 시간 및 지표

- 시간축: 분석기 프레임 수신 `elapsedRealtime`에서 세션 시작 시각을 뺀 밀리초.
  모델 callback 도착 시각은 추론 지연 측정에만 사용합니다.
- 일시정지/재개도 같은 세션 시간축의 control record로 기록합니다.
- 카메라 재연결/회전/백그라운드 진입은 운동을 일시정지합니다. 복귀 후 재개는 다시 보정합니다.
- activeDuration: COUNTING 상태의 시간. COUNTDOWN, 초기/재개 CALIBRATING, PAUSED는 제외합니다.
  COUNTING 도중 추적 재획득 대기 시간은 포함합니다.
- validTrackingDuration: COUNTING에서 연속으로 유효한 원본 프레임 사이의 시간만 합산합니다.
  보정/누락/gap/일시정지 사이의 간격과 마지막 프레임 이후 시간은 더하지 않습니다.
- 평균 분당 점프 = 횟수 × 60000 / validTrackingDuration. 분모 0이면 null.
- 현재 분당 점프 = 60000 / 최근 최대 5개 유효 점프 간격의 평균. 간격이 하나도 없으면 0.
- 마지막 점프 이후 2500ms 지나면 현재 값은 0. 정지 후 긴 간격은 새 리듬에 연결하지 않습니다.
- 일시정지/추적 중단 때 점프 간격 창을 비웁니다. 첫 점프는 리듬이 없다는 이유로 탈락시키지 않습니다.
- peakJumpsPerMinute는 세션 중 현재 값의 최댓값입니다.
- qualityScore는 필수 관절 제공 confidence의 최솟값인 내부 신호 지표이며 검증된 정답 확률이 아닙니다.

실제 작은 점프와 빠른 점프에서 임계값을 조정해야 할 수 있습니다. 조정 시 파라미터 버전을 변경하고
같은 원본 로그를 재판정해 오검출·누락을 수동 점프 시각과 비교합니다.

## v2 변경 이유와 로그 호환

사용자가 작은 점프를 놓치지 않도록 요청하여 골반 상승 시작·최소 진폭과 상승/하강 속도의
크기 임계값을 v1의 20%로 낮췄습니다(80% 감소). 착지 복귀 허용치, 착지 유지 시간,
주기 간격 및 추적 품질 조건은 유지합니다. 착지 복귀 허용치를 줄이는 것은 오히려 조건을 엄격하게
만들므로 이 값에는 80% 감소를 적용하지 않습니다. 골반 속도 반전과 완성된 주기는 계속 요구합니다.

발목은 반드시 유효하게 인식되어야 합니다. 전신 품질, 보정 몸 크기, 무릎 각도, 대상 크기 변화 검사에는
계속 사용되므로 발목 누락을 허용하는 변경은 아닙니다. 단, 발목 상승/복귀 신호는 카운트에 사용하지 않습니다.
골반만의 움직임으로도 카운트될 수 있어 실제 줄 통과/양발 이륙을 보장하지 않습니다.

판정 버전은 jump-detector-2.0.0이며 파라미터 버전은 hip-sensitive-2입니다.
기존 v1 로그의 minimumAnkleLift/landingAnkleLift 필드는 읽을 때 무시합니다.
앱 로그 재생은 현재 판정기와 header에 저장된 골반 임계값을 사용하므로 v1 기록과 결과가 달라질 수 있습니다.
동일 결과 보장은 동일 판정 버전·config·입력에 한정합니다. 기존 결과 파일은 바꾸지 않습니다.
새 기본값 비교는 header의 config만 교체하고 원본 frame/control을 그대로 재생하여 수행합니다.

## 준비 완료 시각 신호 (앱 0.2.1)

세션이 COUNTING이고 판정기 validTracking이 true이며 카메라/앱이 활성 상태일 때
카메라 영역에 2초간 파란 화면과 큰 흰색 체크 표시, 준비 완료 안내를 표시합니다.
그 뒤 카메라를 다시 보여 주고 파란 테두리를 유지합니다. 완료 순간부터 카운팅하며
시각 안내를 위해 운동 시작 시간을 2초 늦추지 않습니다.
추적 중단, 권한/카메라 오류, 백그라운드, 일시정지, 종료 시 준비 표시는 사라집니다.
재보정 후 유효 추적으로 복귀하면 완료 화면을 다시 표시합니다.
파란색은 카운팅 준비 상태이며 정확도나 주변 인물 부재를 보장하는 표시가 아닙니다.
