# K-Rope-Adventure — Android ↔ Godot 실시간 연동 및 테스트 환경 구축

## 1. 프로젝트 개요

K-Rope-Adventure는 어린이 줄넘기 학원을 위한 운동 측정 및 게임화 플랫폼이다.

현재 Android Native 기반의 줄넘기 측정 애플리케이션은 상당 부분 개발되어 있으며, CameraX와 MediaPipe를 이용해 사용자의 움직임을 분석하고 줄넘기 횟수를 측정한다.

다음 개발 목표는 기존 측정 앱과 Godot 4 게임 엔진을 실시간으로 연결하는 것이다.

### 최종 서비스 구성

- **Android 스마트폰 / 태블릿:** 줄넘기 측정, 개인 운동 UI, 게임 참가 및 조작
- **학원 PC:** Godot 4 게임 실행 및 실시간 게임 세션 관리
- **대형 TV / 프로젝터:** PC의 Godot 게임 화면 출력
- **학원 내부 Wi-Fi:** Android 기기와 PC 사이의 실시간 통신
- **외부 클라우드:** 초기 프로토타입에서는 필수 아님

서비스는 개인 운동 모드와 공동 레이드 모드를 모두 지원하는 방향으로 설계한다.

현재는 공동 레이드 게임의 기술적 기반을 먼저 검증한다.

---

## 2. 핵심 아키텍처

### Android Native

기존 Kotlin / CameraX / MediaPipe 측정 구조를 유지한다.

추가 구현 대상:

1. WebSocket 클라이언트
2. 점프 이벤트 전송 인터페이스
3. 서버 연결 설정 UI
4. 개발용 가상 점프 발생기
5. 연결 상태 및 재연결 처리

### PC — Godot 4

Godot 프로젝트에 표준 WebSocket 서버를 구현한다.

주요 기능:

1. Android 클라이언트 연결 수락
2. 클라이언트별 식별 및 세션 관리
3. 점프 이벤트 수신
4. 플레이어별 누적 횟수 표시
5. 연결 상태 표시
6. 향후 레이드 게임 로직과 연결 가능한 이벤트 인터페이스 제공

Android Kotlin의 일반 WebSocket 클라이언트와 호환되는 표준 WebSocket 프로토콜을 사용한다.

Godot의 고수준 멀티플레이 프로토콜 사용을 전제로 하지 않는다. Godot 4의 `TCPServer`와 `WebSocketPeer`를 활용한 서버 구현을 우선 검토한다.

---

## 3. 네트워크 구성

별도의 외부 서버를 구축하지 않는다.

학원 PC가 WebSocket 서버 역할을 담당하며 Android 기기들은 같은 로컬 네트워크를 통해 접속한다.

예시:

- Godot PC: `192.168.0.10`
- WebSocket Port: `8080`
- Android 접속 주소: `ws://192.168.0.10:8080`
- Android Emulator: `ws://10.0.2.2:8080`
- PC 자체 테스트: `ws://127.0.0.1:8080`

IP 주소 및 포트는 설정값으로 관리하며 하드코딩하지 않는다.

동일한 LAN에 연결된 장치 간 통신을 지원해야 하며, 인터넷 연결 없이도 공동 게임이 실행될 수 있도록 설계한다.

실제 배포에서는 학원 네트워크 분리, 방화벽, 클라이언트 인증 등을 고려한다.

---

## 4. Android 측정 이벤트 인터페이스

기존 MediaPipe 기반 측정 알고리즘을 직접 변경하지 않는다.

줄넘기 횟수 판정 결과를 별도 인터페이스로 전달하도록 구성한다.

예시 이벤트:

```json
{
  "type": "jump",
  "player_id": "student_001",
  "session_id": "raid_001",
  "sequence": 105,
  "total_count": 105,
  "timestamp_ms": 123456789
}
```

필드 설명:

- `type`: 이벤트 종류
- `player_id`: 학생 또는 플레이어 식별자
- `session_id`: 게임 세션 식별자
- `sequence`: 이벤트 순서 번호
- `total_count`: 현재 세션의 누적 줄넘기 횟수
- `timestamp_ms`: 측정 시점의 타임스탬프 (기준을 명확히 정의할 것)

실제 구현에서는 기존 앱의 데이터 구조와 학생 식별 방식에 맞게 조정한다.

중복 메시지 처리와 재연결 시 상태 복구를 고려한다.

점프 측정 결과는 네트워크 연결 여부와 독립적으로 유지되어야 한다.

---

## 5. Android 개발자 설정 UI

개발 및 테스트 중 매번 APK를 수정하지 않도록 앱 내부에 설정 화면을 추가한다.

필요한 항목:

- WebSocket 서버 IP 또는 호스트명
- WebSocket 포트
- 연결 / 연결 해제
- 현재 연결 상태
- 실제 측정 / 가상 측정 모드 전환
- 가상 점프 발생 속도 설정 (선택)

서버 설정값은 앱 재실행 후에도 유지되도록 저장한다.

설정 변경 후 새로운 서버로 재연결할 수 있어야 한다.

개발용 설정과 가상 측정 기능은 Debug 빌드에서만 활성화하는 방향을 우선 검토한다.

---

## 6. 가상 줄넘기 측정기 구현

실제 Android 기기 없이도 Godot 게임을 테스트할 수 있도록 별도의 PC 테스트 클라이언트를 만든다.

Python 기반 WebSocket 클라이언트 구현을 우선 고려한다.

### 필수 기능

- Godot WebSocket 서버 연결
- 가상 학생 ID 지정
- 점프 이벤트 자동 생성
- 초당 점프 횟수 설정
- 누적 횟수 관리
- 시작 / 일시정지 / 종료
- 다중 가상 학생 생성

### 추가 테스트 시나리오

- 학생별 다른 줄넘기 속도
- 여러 학생의 동시 점프
- 중간에 점프를 멈추는 상황
- 네트워크 연결 해제 및 재접속
- 중복 이벤트 전송
- 이벤트 순서 변경
- 실제 운동 이벤트 기록 재생

가상 측정기는 실제 Android 앱과 동일한 메시지 규격을 사용해야 한다.

이를 통해 Godot은 실제 Android 기기와 가상 측정기를 동일한 클라이언트로 처리할 수 있어야 한다.

---

## 7. Godot 테스트 화면

첫 번째 구현에서는 완성형 게임을 만들지 않는다.

연동 상태를 확인할 수 있는 간단한 디버그 UI를 제작한다.

### 표시 항목

- WebSocket 서버 실행 상태
- 서버 IP 및 포트
- 연결된 클라이언트 수
- 각 학생의 ID
- 각 학생의 누적 줄넘기 횟수
- 마지막 이벤트 수신 시각
- 클라이언트별 연결 상태
- 전체 누적 줄넘기 횟수

점프 이벤트를 수신할 때마다 해당 학생의 숫자가 갱신되도록 구현한다.

선택적으로 간단한 캐릭터 애니메이션이나 시각 효과를 발생시킨다.

향후 레이드 게임에 재사용할 수 있도록 네트워크 수신 로직과 게임 UI 로직을 분리한다.

## 8. 권장 개발 및 테스트 워크플로

### A. 평상시 게임 개발

- Godot Editor에서 F5로 게임 실행
- PC에서 Python 가상 측정기 실행
- 다수의 가상 학생 연결
- 실시간 점프 이벤트 전달
- Godot 화면에서 결과 확인

Android 기기나 APK 빌드가 필요하지 않아야 한다.

### B. 실제 통합 테스트

- Android 태블릿에서 기존 측정 앱 실행
- Godot PC와 동일한 Wi-Fi에 연결
- 앱에서 서버 IP 설정
- 실제 줄넘기 측정
- PC Godot 화면에서 이벤트 수신 확인

Godot 게임 로직만 수정한다면 Android 앱을 다시 빌드하지 않고 테스트할 수 있어야 한다.

### C. 최종 학원 환경 테스트

- 여러 대의 Android 기기 사용
- 학원 PC에서 Godot 게임 실행
- PC를 HDMI로 TV에 연결
- 다중 사용자 동시 측정
- 통신 지연 및 안정성 확인
- 연결 끊김과 복구 테스트

## 9. 개발 시 유의사항

1. 기존 CameraX / MediaPipe 측정 기능과 동작을 최대한 유지한다.
2. 기존 측정 알고리즘의 변경은 별도 요청이 없는 한 수행하지 않는다.
3. Android와 Godot 사이의 통신 프로토콜을 명확히 분리한다.
4. 네트워크 오류가 줄넘기 측정 자체를 중단시키지 않도록 한다.
5. 클라이언트별 이벤트 순서를 관리하여 중복 집계를 방지한다.
6. Godot의 네트워크 처리와 렌더링 로직을 분리한다.
7. 실시간 이벤트 수신으로 게임 메인 루프가 장시간 블로킹되지 않도록 한다.
8. 다중 클라이언트 접속을 고려해 설계한다.
9. 향후 개인 게임, 팀 대항전, 공동 레이드로 확장할 수 있도록 한다.
10. 초기 단계에서 불필요한 외부 서버나 복잡한 클라우드 인프라를 도입하지 않는다.

## 10. 구현 우선순위 및 완료 기준

### Phase 1 — 통신 기반 구축

Android WebSocket 클라이언트와 Godot WebSocket 서버의 연결.

**완료 기준:** 실제 Android 단말에서 보낸 테스트 메시지가 PC Godot에 정상 표시된다.

### Phase 2 — 측정 이벤트 연결

MediaPipe 점프 판정 결과를 WebSocket으로 전달.

**완료 기준:** 실제 줄넘기 횟수가 Godot 화면에 실시간 표시된다.

### Phase 3 — 가상 측정 환경 구축

Python 가상 측정기 및 다중 학생 시뮬레이션.

**완료 기준:** Android 기기 없이도 가상 학생 여러 명의 점프 이벤트를 Godot에서 처리한다.

### Phase 4 — 안정성 검증

연결 해제, 재연결, 중복 이벤트, 네트워크 지연 테스트.

**완료 기준:** 통신 장애 발생 후 정상 복귀하며 이벤트 중복 집계가 발생하지 않는다.

### Phase 5 — 게임 연동 준비

측정 이벤트를 Godot의 게임 로직에 연결할 수 있는 인터페이스 구성.

**완료 기준:** 점프 이벤트에 따라 캐릭터 또는 테스트 오브젝트가 반응한다.

## 11. Codex에 요청하는 작업

우선 기존 Android 프로젝트의 구조를 분석할 것.

특히 다음 항목을 확인한다.

- MediaPipe 측정 파이프라인
- 줄넘기 카운트가 확정되는 위치
- 카운트 이벤트를 외부로 전달할 수 있는 구조
- 기존 학생 및 운동 세션 모델
- 현재 Android UI 및 개발자 설정 구조
- 기존 네트워크 관련 코드의 존재 여부

분석을 마친 후 다음 내용을 제시할 것.

1. 기존 코드에 미치는 영향
2. 추가 또는 변경할 파일 목록
3. WebSocket 통신 인터페이스 설계
4. Android와 Godot의 공통 메시지 규격
5. 테스트 방법과 검증 기준
6. 단계별 구현 계획

**중요: 기존 프로젝트 구조를 확인하지 않은 상태에서 대규모 리팩터링을 수행하지 말 것. 기존 측정 기능을 보존하면서 최소한의 변경으로 실시간 연동 시스템을 추가하는 것을 최우선으로 한다.**

Godot 프로젝트가 별도로 존재하지 않는다면, 통신과 이벤트 시각화만 담당하는 최소 테스트 프로젝트를 새로 구성한다.

최종 목표는 Android 앱을 매번 다시 빌드하지 않고도 PC의 Godot Editor에서 게임과 멀티플레이 로직을 빠르게 개발하고 테스트할 수 있는 환경을 구축하는 것이다.
